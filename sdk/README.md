# hoist SDK

The `hoist/sdk` package is a lightweight runtime wrapper for Go HTTP servers. It provides zero-config deployment with automatic health checks, Prometheus metrics, structured logging, and graceful shutdown.

---

## Package Structure

```
sdk/
├── sdk.go          # Start(), main entry point
├── config.go       # Env var parsing, Config struct
├── server.go       # HTTP server, graceful shutdown, signal handling
├── health.go       # Health check handler, custom check registration
├── metrics.go      # Prometheus metrics, /metrics endpoint
├── logging.go      # Structured JSON logger
├── middleware.go   # Request logging, metrics, recovery middleware
├── go.mod
└── README.md
```

---

## Quick Start

```go
package main

import (
    "net/http"
    "github.com/you/hoist/sdk"
)

func main() {
    mux := http.NewServeMux()
    mux.HandleFunc("/hello", func(w http.ResponseWriter, r *http.Request) {
        w.Write([]byte("Hello!"))
    })

    hoist.Start(mux)
}
```

That's it. One function call. The SDK handles the rest.

## Configuration

The SDK loads configuration from multiple sources with this precedence:

**defaults → env vars → hoist.json → .hoist.local.json**

### hoist.json

Generated by `hoist init` and committed to git:

```json
{
  "app_name": "my-api",
  "port": 8080,
  "log_level": "info",
  "log_format": "json",
  "metrics_enabled": true,
  "health_path": "/healthz"
}
```

### .hoist.local.json

Gitignored file for developer-specific overrides:

```json
{
  "port": 3000,
  "log_level": "debug"
}
```

Only fields present in `.hoist.local.json` override `hoist.json`. Missing fields fall back.

### Environment Variables

| Variable                | Default    | Description                         |
| ----------------------- | ---------- | ----------------------------------- |
| `HOIST_PORT`            | `8080`     | Port to listen on                   |
| `HOIST_APP_NAME`        | `app`      | App name (for logs/metrics)         |
| `HOIST_LOG_LEVEL`       | `info`     | Log level: debug, info, warn, error |
| `HOIST_LOG_FORMAT`      | `json`     | Log format: json, text              |
| `HOIST_METRICS_ENABLED` | `true`     | Enable Prometheus metrics           |
| `HOIST_HEALTH_PATH`     | `/healthz` | Health check endpoint path          |

## Health Checks

The SDK automatically exposes a health check endpoint at the configured path (default `/healthz`).

### Default Behavior

Returns HTTP 200 immediately. The daemon polls this before flipping traffic during deploys.

### Custom Health Checks

Register custom checks to verify dependencies:

```go
hoist.AddHealthCheck("database", func() error {
    return db.Ping()
})

hoist.AddHealthCheck("redis", func() error {
    return redisClient.Ping(context.Background())
})
```

If any check returns an error, `/healthz` returns HTTP 503.

## Metrics

Prometheus metrics are automatically collected and exposed on `/metrics`.

### Default Metrics

- `http_requests_total{method, path, status}` - Request counter
- `http_request_duration_seconds{method, path}` - Request duration histogram

Disable metrics by setting `metrics_enabled: false` in `hoist.json`.

## Graceful Shutdown

On SIGTERM or SIGINT:

1. Stop accepting new connections
2. Wait for in-flight requests to complete (30s timeout)
3. Close server cleanly

---

## Middleware Stack

The SDK wraps your handler with these middleware (applied in order):

1. **Recovery** - Catches panics, returns 500
2. **Request ID** - Injects `X-Request-ID` header
3. **Metrics** - Collects request metrics
4. **Logging** - Structured JSON logs (method, path, status, duration)

## API Reference

### Start(handler http.Handler)

Starts the HTTP server with the given handler. Blocks until shutdown.

```go
hoist.Start(mux)
```

### AddHealthCheck(name string, check func() error)

Registers a custom health check function. Called on every `/healthz` request.

```go
hoist.AddHealthCheck("database", func() error {
    return db.Ping()
})
```
